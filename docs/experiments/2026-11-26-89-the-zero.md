# EXP-89: where 0 V is, per channel and range, and the trigger level in volts

- **Date:** 2026-11-26
- **Unit:** my unit
- **Build:** zeros and the CH2 sweep on `guest-coldtrace` `Nov 26 2026
  17:24:15` (EXP-88); the CH1 sweep on `20:54:15` (first zero build); the
  boot-code check and the trigger check on `21:09:14` (this change)
- **Setup:** DC coupling during each sweep (restored after), timebase 0x08,
  AUTO. In order: CH1 shorted (probe tip on its ground clip) with GEN into
  CH2 by a BNC cable; CH2 grounded, CH1 open; GEN into CH1, CH2 grounded
- **Source scale:** EXP-80, GEN = 0.7937 mV per DAC code
- **Status:** CONFIRMED

## 1. Problem

The gains are absolute since EXP-83/84 (through GEN and a self-calibrated
Rigol), so a difference of counts is a voltage. An absolute voltage (a
trigger level, a DC level, a 0 V marker) also needs the count that means
0 V. EXP-84 saw it at 42-50 counts and left per-range values open. Without
it the trigger level could only be shown as a step and an FPGA code, and the
"1"/"2" reference flags (EXP-88) marked the fit's centre, not 0 V.

## 2. Hypothesis

- The zero is a property of the offset reference (DAC1/PA4 for CH1,
  TMR13/PA6 for CH2), injected behind the attenuator: with the input
  shorted, every range sits within a few counts of the others, and one
  counts-per-code slope per channel serves every range. Falsifier: the slope
  differs between ranges by more than the noise, or the zero scales with
  the range's gain.
- GEN's DC levels give the same zero by extrapolation, up to GEN's own 0 V
  error b, which must then be the same on every range (b / gain counts).
  Falsifier: an intercept that disagrees with the short by more than GEN's
  -6..+35 mV allows.

## 3. Procedure

Scripts in `reverse_engineering/captures/exp89/` (they import `loop.py` from
exp84):

- `zero.py ch1` / `zero.py ch2`: input shorted, DC; every range 0-9 at three
  offset codes (CH1 DAC1 2048 / 1536 / 2560; CH2 TMR13 2544 / 2048 / 3040);
  4 records per point; mean, sd, frame-to-frame spread, railed fraction.
  Restores range, coupling and the boot code.
- `gensweep.py ch2 2048 [ranges]`: CH2 at TMR13 2048, GEN DC at code 20 and
  the 0.1 V step, then up to six more levels below 200 counts; fit counts
  against 0.7937 mV x code. Points that touch the ceiling are dropped (first
  run: at 255; corrected to 227 after it, see results, and ranges 4/8/9
  rerun). Then `gensweep.py ch1 2048` with GEN moved to CH1.
- `analyse.py`: intercept minus shorted zero per range, as GEN's offset.
- `dac1_linearity.py`: GEN held at its lowest level into CH1, DAC1 2048 to
  3072 in five steps on ranges 5 and 9 (CH1's short only had two codes).
- `trigcheck.py`: GEN 5 Hz sine into CH1, range 5, DC, timebase 0x12, rising;
  levels at 30/50/70 % of the span, NORMAL, 6 records each; r[512] (the
  trigger sample of a time-ordered record) against code - 28, and the
  firmware's volts (`fpga scope zero`) against r[512] through the model.

## 5. Results

### Zero with the input shorted (counts, offset reference at code 2048)

Least-squares per range with one slope per channel. CH1's slope also uses
`dac1_linearity.py` (each of its two runs with its own intercept, since GEN
adds a constant). Every measured point is within 0.29 counts (CH1, 30
points) / 0.27 (CH2, 30) of the model, rms 0.14 / 0.14.

- Slope: 0.12137 (CH1) / 0.12195 (CH2) counts per code. The shorted pair
  alone gave CH1 0.12108 (ten ranges, sd 0.0003); over 2048..3072 with GEN
  held, 0.12173 (r5) / 0.12161 (r9), linear within 0.08 / 0.26 counts. CH1
  at 1536 rails low on every range.
- Noise: sd 0.3-0.9 counts per record, frame-to-frame 0.00-0.08.
- Ranges 0-4 repeat 5-9 within 0.3 counts on both channels (0/5, 1/6, 2/7,
  3/8, 4/9).
- Ranges 0-3 do **not** rail with the input shorted (unit #1, EXP-11: they

### Where 0 V sits at boot

CH1 boots with DAC1 at 2048 (0 V at 48.83 counts on range 5); CH2 booted
with TMR13 at 2544, unit #1's code for a mid-scale MEAN, which put 0 V at
101-106 counts on my unit, so a 0-3 V signal on range 5 clipped at CH2's
227 ceiling. The user chose 0 V near the bottom on both. `fpga_init` now
arms TMR13 at `scope_cal_offset_for_zero(2, 5, CH1's zero)`: 2114.

### Trigger level in volts (CH1, `trigcheck.py`)

GEN 5.000 Hz, span 50..172 counts, slope at the trigger 0.9-1.0 count per
sample; every record time-ordered.

| level | code | code - 28 | r[512], 6 records | firmware | r[512] as volts |
|---:|---:|---:|---|---:|---:|
| +9 | 139 | 111 | 111 112 111 112 112 111 | +1244 mV | +1254 mV |
| -11 | 115 | 87 | 89 89 89 89 89 89 | +764 mV | +804 mV |
| +28 | 162 | 134 | 134 134 134 134 134 134 | +1704 mV | +1704 mV |

The 28 holds on my unit's CH1 (offsets 0 / +2 / 0, EXP-56's band is ±3),
and the printed level is within 2 counts (40 mV, 1/16 division) of the
sample the trigger fired on.

- **CH2 clips at 227 counts, not 255**: points read 227.0 with sd 0.0
  (range 0 at code 144, range 4 at code 1881). The first run treated only
  255 as railed, so range 4's top point bent its fit (5.2 counts residual);
  dropped, the residual is 0.65.
- **Ranges 2 and 3 are linear, sensitive ranges on CH2** (1.97 and 3.91
  mV/count). Ranges 0 and 1 are more sensitive still; GEN's 0.1 V step is
  124 counts there, so two levels at most fit and the first range 0 pair
  was clipped. Not measured.
- The weighted GEN offset is +7.0 ± 0.4 mV, but chi² is 40.6 on 7 degrees of
  freedom: the ranges disagree by up to 0.3 counts, more than their stated
  errors. Expressed in counts, every intercept is within 0.3 of its shorted
  zero. Read as: the zero is known to about ±0.3 counts, and GEN's 0 V is
  about +7 mV (inside the Rigol's -6..+35 mV, more tightly).

## 6. Blind spots

- The zero's ±0.3 counts is set by an undithered 8-bit converter (sd 0.5
  counts); averaging more records does not remove a code-width bias.
- One session, one temperature. Drift is not measured.
- The trigger offset of 28 is now checked on my unit's CH1 (range 5). On
  CH2 the volts still assume it.
- Ranges 0-1 have zeros but no gains, so they show no volts.
- The boot code matches the channels on range 5 only: at a fixed code the
  zeros differ by range (CH1 43.6-48.8, CH2 40.7-44.9 at 2048), so on other
  ranges the two 0 V rows sit up to ~5 counts apart. The flags and volts
  read the zero per range, so they stay right.
- The X-Y view servos both offsets to centre its signal and does not put
  them back; after a visit, 0 V sits elsewhere (the flags and volts follow,
  since they read the codes in force).
- The popup text was not seen on the glass (it times out before a
  screenshot); `fpga scope zero` prints the same function's result.
- The zero with a 10x probe attached is assumed unchanged (it is set behind
  the BNC); not measured.

## 7. Conclusion

- **Established:** 0 V per channel and range on my unit to about ±0.3
  counts, confirmed through both channels by the same generator (its 0 V
  error +7.0 / +8.0 mV); the offset references move every range by one
  slope (0.1214 / 0.1220 counts per code), so 0 V can be placed anywhere by
  arithmetic, and the boot code placed CH2's at 48.69 against 48.85
  predicted. Both channels clip at 227 counts. Ranges 3 and 4 are MEASURED
  and range 2 PROVISIONAL on both channels (63 / 126 / 252 mV per
  division). On CH1 the trigger fires within 2 counts of the volts the
  popup prints.
- **Not established:** the 28 offset on CH2; gains for ranges 0-1; drift.
