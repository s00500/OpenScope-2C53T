# EXP-90: AUTO is an autoset; AUTO no longer freezes on dropped edges

- **Date:** 2026-11-26
- **Unit:** my unit
- **Build:** `guest-coldtrace`, this change (`Nov 26 2026 22:41:51`); earlier
  runs on 22:26:37, 22:31:41 (status readout) and 22:35:56 (fill target)
- **Setup:** GEN into CH2 by a BNC cable, CH1 open; true-scale view
- **Status:** CONFIRMED (5/5 cases); the AUTO freeze FIXED, its cause (why
  every record is called the wrong edge with CH1 off) NOT established

## 1. Problem

In the scope's time view AUTO was the mask key; on stock (and in our own UI
spec) it is an autoset. The user asked for the autoset and for the mask key
to move to the trigger panel. Can the calibrated volts (EXP-83/84/89) and the
measured timebases (EXP-81) choose V/div, time/div and the trigger from the
signal alone, on the instrument, without blocking the input task (2 s health
deadline) or copying records (RAM is tight)?

## 2. Hypothesis

The pure decisions (`ui/autoset.c`, host-tested) applied by a state machine
stepped from the input task (`tasks/scope_autoset.c`) pick, for GEN into
CH2: a 1 kHz sine (about 2.6-3 Vpp) on range 6 and 0x0D with both channels
on, range 5 alone; a 0-3 V 20 kHz square on range 6 and 0x09; 1.5 V DC on
range 5 with the timebase kept; and nothing on either input ends as "no
signal", range 5, timebase kept. CH1, open, always ends on range 5. The
trigger moves to CH2 with the level at the signal's middle. Falsifier: any
case ending elsewhere.

## 3. Procedure

- `ui/autoset.c`: levels at 0.5 / 99.5 % by counting passes (no histogram),
  clipping (>= 0.5 % at 0 or the 227 ceiling), cycles per sample from rising
  mid-level crossings with hysteresis, the range picker (2..9, 6..215 counts at
  the range's 0 V, peak to peak within a target in divisions), the timebase
  picker (measured codes, about 3 cycles on 320 columns), position and
  trigger level. `test-autoset` (EXP-89's level/code pairs among its cases).
- `tasks/scope_autoset.c`: VERT (each channel until its range settles; a
  clipped record steps two ranges coarser) -> FREQ (5 M, 500 k, 50 k, 5 k,
  500 S/s, fastest first) -> VERT again -> positions, trigger, AUTO mode.
  Each step waits for two commits after a change (generation counter), with
  a deadline; any key cancels. `fpga scope autoset` prints its state.
- Mask key -> trigger panel row 4 (`test-trig-menu`).
- `captures/autoset/autoset_check.py`: per case, GEN set, deliberately wrong
  start settings, AUTO, then wait for `phase off` and read back.

**Preconditions verified by readback:** build per run (`shell version`);
every case's start settings via `set`, read back by `get`; settings restored
to the session start after each run (`settings diff: {}`).

## 5. Results

Final run (22:41:51), 5/5:

| case (GEN into CH2) | start | CH2 range | timebase | trigger | time |
|---|---|---|---|---|---:|
| sine 1 kHz, both on | r9, 0x08 | 6 (2.99 Vpp, 2.4 div) | 0x0D (1029 Hz counted) | CH2, code 116 = mid 88 + 28 | 2.3 s |
| square 20 kHz, both on | r2 (clipped), 0x14 | 6 (3.11 Vpp) | 0x09 (20.7 kHz) | CH2, code 116 | 4.4 s |
| DC 1.5 V | r9, 0x0E | 5 (level 1.47 V) | 0x0E kept (no cycles) | CH2, code 151 = mid 123 + 28 | 6.6 s |
| off | r9, 0x0B | 5, "no signal" | 0x0B kept | unchanged | 3.4 s |
| sine 1 kHz, CH1 off | r9, 0x08 | 5 (2.94 Vpp, 4.6 div) | 0x0D (1000 Hz) | CH2, code 151 = mid 123 + 28 | 3.4 s |

CH1 (open) ended on range 5 in every case. Screenshots (weak evidence,
`captures/autoset/device-*.png`): 2.5-2.6 cycles of each periodic signal,
centred in CH2's half (or the screen, alone), the DC level a flat line on the
half's middle.

How it got there (earlier runs, kept because each changed something):

1. 22:26:37, 3/5. **square-20k** went to range 7: it measures 3.16 Vpp with
   its overshoot, 2.51 div on range 6, over the first fill target (2.5 div
   per half, 5.0 alone), so it was drawn at 1.25 div. The target became about
   85 % of the space (2.8 / 5.5 div): a UI choice, recorded as such.
   **sine-1k-ch2-alone** changed the range and stopped: the test detected the
   end as "settings quiet for 3 s", which an autoset waiting between steps
   also is, so the next case's AUTO press stopped the previous autoset. The
   test now waits for the state readout's `phase off`.
2. 22:35:56, 4/5. **sine-1k-ch2-alone** again: the state readout showed it
   ended in VERT with the capture counter 4 short of its wait. Reproduced 3/3
   by hand, and then **without the autoset**: with CH1 off, CH2 on range 5,
   0x08, the sine on CH2 and the trigger level inside it, the capture counter
   stops (0 commits in 3 s; range 9, level outside the signal: 45-90/s).
   `fpga edgefilter` and `status`: PC0 +16, edge filter dropped +16, kept and
   unclassified +0 in 2 s. AUTO's fallback runs from the last handover
   (EXP-72), handovers kept coming and were all dropped, so AUTO froze.
   Fix (`fpga.c`, edge filter): in AUTO, once nothing has been committed for
   a whole budget, a dropped record is shown (`acq_edge_starved`). After: gen
   170 -> 184 in 2 s, starved +7; NORMAL control unchanged (above).

## 6. Blind spots

- One unit, one generator, five cases, CH2 only (CH1 was open throughout).
  Signals above 50 kHz, below 15 Hz, with noise or a DC offset plus a small
  ripple were not tried on the bench (the picker's host tests cover the
  arithmetic for some of these).
- Why every triggered record is classified as the wrong edge with CH1 off is
  not known (a guess: the record's un-rotation or the classifier reads CH1);
  the fix makes AUTO show something, it does not make the edge filter right
  in that state. NORMAL still holds there, as before.
- The 0 V a range is picked against is the EXP-89 zero at the offset code in
  force; after the X-Y view has moved the offsets it still holds (the model
  takes any code), but that was not run.
- The emulator cannot run the autoset (its synthetic feed does not advance
  the capture generation); it starts and times out there.

## 7. Conclusion

- **Established:** AUTO is an autoset on my unit: 5/5 cases from wrong
  settings to the predicted range, timebase and trigger in 2.3-6.6 s. The
  mask key is the trigger panel's Mask row. AUTO no longer freezes when the
  edge filter drops every record.
- **Not established:** the edge filter's verdicts with CH1 off; the autoset
  on CH1 and on signals outside the five cases.
